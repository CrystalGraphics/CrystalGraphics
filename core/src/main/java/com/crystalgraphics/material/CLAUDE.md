## What This Package Is

The shader asset and its programs, and the runtime property values `CgMaterial` and callers set. A `.shader` is read
into a `CgShaderSpec` and written into GLSL in `material/shader/`.

## Programs from a spec

`CgMaterialShaderMap` asks `CgGlslWriter` (`material/shader/`) for each pass and keyword set's `CgGlslProgram`, then
preprocesses and compiles it. What the writer emits, and in which order: `shader/CLAUDE.md` and `CgGlslWriter`'s
javadoc. A `vec3` property fails to read (std140 pads it); `CgMaterialProperty.fromDecl` refuses one too, for a path
that bypasses the reader.

## Keyword Variant Internals

`CgMaterialShaderMap` holds one program per (pass name × keyword set), for one spec:

- `ProgramKey(String passName, Set<String> keywords)`; keyword equality is set-based.
- The no-keyword variant of each pass is compiled by `recompile()` into a new map; keyword variants on the first
  `getOrCompile(passName, keywords)` or `precacheVariant`.
- The generated depth pass is kept under `ProgramKey("Depth", emptySet)`.

**No shadow pass**: the world's shadows are ray-traced from each pixel (`CgWorldLights`, Unreal's MegaLights), so
nothing draws from a light's side.

**Depth auto-generation (`CgMaterialShaderMap.autoGenDepth`, from `recompile()`):**
- Runs when `queue() < TRANSPARENT_THRESHOLD`.
- Every opaque material needs a correct depth variant.
- Writes the Forward pass's depth program: `CgGlslWriter.writeDepth(...)`.
- Three-case GLSL: (1) simple vertex → minimal `CG_MATRIX_MVP` transform; (2) complex vertex → forward body verbatim; (3) alpha-clip → forward vertex + forward fragment (preserves `discard`).
- On GL link failure: logs an error and continues without a depth variant — non-fatal regardless of first/hot-reload.
- On success: stored as `ProgramKey(CgRenderPassVariant.DEPTH.lightModeName(), emptySet)`.

**Compile flow for a keyword variant:**
1. `CgMaterial.keyword("NAME", true)` answers its family's material with `NAME` among its enabled keywords, made once
   (`CgMaterialProxy.keyword`, cached by keyword mask); keyword names are validated against the spec, compiling nothing.
2. Its proxy's `pipeline(kind)` resolves the Forward pass under those keywords; the program is compiled at the
   pipeline's first draw or `precache()`.
3. `getOrCompile()` asks the committed map, which answers a hit at once.
4. On a miss the map generates the variant (`CgGlslWriter.write(spec, pass, buffers, block, keywords)`), links, wires and keeps it.

**Hot-reload interaction:**
- `recompile()` builds a new map and, once its passes link, deletes the old one.
- Each material and instance rebuilds its values from the new spec at its next capture (`syncPropsToParse`).

## Programs (`CgShader`, formerly `material`)

What a material's pass and keyword set, or a kernel, compiles into: the program as written
(`CgGlslCompiler.compileExplicit`) that its device pipelines are built from. Not API: a consumer's shader is a material
(`CgMaterial`) or a kernel (`CgKernel`); there is no public way to compile GLSL text or set a uniform by name (rhi SH9,
Unreal's material and global shaders).

### Class map

| Class | Job |
|---|---|
| `CgShader` | A material program from generated sources: `compile` (now) or `submit` (on a worker), `isReady`, `isCompiled`, `getLastCompileError`, `explicit()`, `sceneReads()`, its modules on a device (`deviceModule`), `delete`. A failure is kept, never thrown, but by `explicit()` |
| `CgShaderCompile` | A compile under way: on a job worker where the installed compiler compiles on any thread (shaderc), else run by the first thread that asks (the native compiler, which needs the device's context) |

### Invariants

- `format` places the vertex inputs: attribute `i` at location `i`; null where the source places them.
- The owner of a `CgShader` deletes it: a material's map. A compile still running when it is deleted finishes unread.
- What a program samples of the scene is its own layout's answer (`sceneReads`), so a keyword variant answers for
  itself.
